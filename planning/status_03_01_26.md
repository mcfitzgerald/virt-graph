  VG/SQL Project Status

  What It Is

  VG/SQL enables graph-like queries over relational SQL data without migration. Three components: a LinkML ontology declaring graph structure,
  Python handlers for traversal/pathfinding/network algorithms, and Claude Code as the orchestration layer that reads the ontology and
  dispatches queries.

  Current State: v1.3.1 on ontology-core branch

  The project has evolved through two phases:

  Phase 1 (v0.1–0.9.x): Built the full stack — PostgreSQL data generator (~2M rows, 26 tables), handlers, Neo4j benchmarking, 85 benchmark
  questions. All archived to git history when you created ontology-core.

  Phase 2 (v1.0–1.3.1): Stripped to the ontology + handler framework. Key milestones:
  - v1.0 — Clean branch, FMCG reference ontology
  - v1.1 — Metamodel v3.0 with kinetic extensions (axioms, state machines, flows, actions, scenario params). PCG ontology replaces FMCG. 9
  state machines, 10 flow configs, 6 axioms, 3 action sets.
  - v1.2 — PCG ontology v2.0: 30→50 relationships, polymorphism, transport network, SKU alias chain, BOM hierarchy, context blocks. All FKs
  mapped.
  - v1.3 — scm_base.yaml with abstract classes/mixins/enums, class hierarchy (Location, TransactionDocument, LineItem), SchemaView integration
  - v1.3.1 — Repo reorganization (files moved to logical locations, Makefile removed)

  What's Open (from gap analysis)

  1. Kinetic handlers (HIGH) — flow_analysis(), state_analysis(), scenario_analysis(). The metadata is fully declared in the ontology (9 state
  machines, 10 flow configs, 3 scenario param sets). No handler implementations yet — Claude generates ad-hoc SQL for these patterns today.
  2. Axiom checker (MEDIUM) — validate_axioms() to run the 6 declared SQL axiom expressions against live data. Declarations exist, no runner.
  3. Context-stuffing / orchestration (MEDIUM) — No system prompt template loading the ontology files. No wired-up "intelligence layer" that
  reads ontology → builds prompt → dispatches. The conceptual pipeline (Phase 4 in whitepaper) isn't implemented.
  4. LinkML polish (LOW) — required: true on NOT NULL attrs, more enums, additional sql_filter annotations.

  No Database Running

  The ontology-core branch has no Docker/DB infrastructure. The PCG schema DDL is at pcg_example/pcg_schema.sql for reference only. All handler
   tests run against ontology metadata, not live data.
